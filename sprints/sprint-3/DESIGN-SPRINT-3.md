# Дизайн-спека — Спринт 3: получение сообщений

База: `design/DESIGN.md`, `design/SPRINT-1.md` (C6 Banner, C5 Spinner), `design/SPRINT-2.md` (§2 ChatCell, §3 Bubble/статусы, §4 Composer), токены `src/styles/tokens.css`. Задачи 1, 3, 6 — без UI (кроме баннеров) и здесь не разбираются. 360 и 1440, обе темы.

## 1. Входящий пузырь [DS:bubble-in]
Геометрия и цвета — SPRINT-2 §3 Bubble, вариант incoming. Уточнения:
- Ряд выровнен `flex-start`; пузырь bg `--bubble-in-bg`, текст `--bubble-in-text`, мета — только время `--bubble-in-time` (статусов у входящих нет, иконки нет, ширина меты меньше — текст обтекает ближе).
- Хвостик: нижний **левый** угол 6px у последнего в группе входящих.
- Группа входящих подряд: gap 2, у промежуточных все углы 16.
- Чередование авторов: gap 8. Аватара рядом с пузырём нет (1:1 чат, как в MAX).
- Время — время отправки собеседником.
- Появление нового входящего, когда пользователь внизу ленты: пузырь рендерится сразу, лента скроллится `smooth` (reduced-motion → мгновенно). Без fade/slide-анимаций пузыря.
- a11y: контейнер ленты уже `role="log" aria-live="polite"`; каждый новый пузырь — `aria-label` «Анна, 14:05: текст» формируется из атрибутов, не визуально.

### Плейсхолдер неподдерживаемого типа [DS:unsupported]
Тот же пузырь (incoming или outgoing — если с телефона отправили фото), внутри вместо текста: иконка 16 слева + текст курсивом, `--font-body` `font-style: italic`, цвет `--bubble-unsupported-fg-in` / `-out`, gap 6, `align-items:center`. Мета (время) как обычно.
| Тип | Иконка (Lucide) | Текст |
|---|---|---|
| любой неподдерживаемый | `file` | Сообщение этого типа не поддерживается |
Один текст на все типы — минимализм, как требует задача. В превью списка — тот же текст без курсива, `--text-tertiary`.

## 2. Шапка чата «Имя + номер» (задача 2)
Уточняет SPRINT-2 §3 Header: когда название чата — имя, шапка двухстрочная: Title `--font-title` 17/24 «Анна» → под ним `--font-description` 12/14 `--text-tertiary` «+7 999 123-45-67». Колонка вертикально по центру 56px (24+2+14 = 40, паддинг 8). Обе строки ellipsis. Если название — номер, вторая строка не рендерится (как в спринте 2).
Avatar 36: с появлением имени — инициал (первая буква, верхний регистр, `--font-body-strong` белый) вместо иконки user; тот же градиент по `chatId`. В списке — аналогично в 48 с `--font-title`. Смена иконка→инициал без анимации.

## 3. Статусы своего сообщения [DS:bubble-out], [DS:message-status]
Расширяет SPRINT-2 §3 «Статусы». Иконка 16 в мете, после времени, gap 4.
| Статус | Иконка | Цвет | Примечание |
|---|---|---|---|
| отправляется | `clock` | `--bubble-out-status`, opacity .7 | |
| отправлено | `check` | `--bubble-out-status` (#ffffffe0) | |
| доставлено | `check-check` | `--bubble-out-status` | |
| прочитано | `check-check` | `--bubble-out-status-read` (#fff, 100%) | На синем разница e0→ff слабая, поэтому дополнительно **`stroke-width: 2.5`** у прочитанных vs 2 у остальных. Не вводим второй цвет — на градиенте он не читается, у MAX тоже белые |
| не доставлено | как «не отправлено» SPRINT-2 | | alert-circle слева от пузыря + строка «Не доставлено. Повторить» |
Переходы: только вперёд, crossfade 150ms. «Повторить» на «не доставлено» → clock, строка исчезает.
В превью списка (слот справа, SPRINT-2 §2): `clock` / `check` / `check-check` `--icon-tertiary`; прочитано → `check-check` `--text-link`; ошибка → `alert-circle` `--bubble-status-error`. Слот показывается только если последнее сообщение — своё и нет непрочитанных.

## 4. Счётчик непрочитанных [DS:unread-badge]
Готов в SPRINT-2 §2 (слот строки 2). Уточнения:
- min-width 20, h 20, padding 0 6, radius pill, bg `--counter-bg`, текст 12/16 500 `--counter-text`, `font-variant-numeric: tabular-nums`. 1 → круг 20×20; 12 → 26×20; 99+ → 34×20.

- `aria-label` «12 непрочитанных» на бейдже; на элементе списка в `aria-label` добавляется «, 12 непрочитанных».
- Заголовок вкладки: `(3) MAX-чат`; 0 → `MAX-чат`. Favicon не меняем.

## 5. Кнопка «↓ Новые сообщения» [DS:new-messages-button]
Заменяет задел «кнопка вниз» из SPRINT-2 §3.
- Позиция: `position:absolute; right: var(--fab-offset) 16; bottom: 16` относительно MessageList (над composer). На mobile right 12.
- **Без числа:** круг `--fab-size` 40, bg `--scroll-fab-bg`, shadow `--scroll-fab-shadow`, иконка `arrow-down` 20 `--icon-primary`. Показывается, когда пользователь дальше `--new-msgs-threshold` 100px от низа **и** есть непросмотренные новые (по задаче 5 — только при новых; просто «далеко от низа» без новых — не показываем, минимализм).
- **С числом:** тот же круг + бейдж сверху по центру (`top:-6; left:50%; translateX(-50%)`), как unread-badge: min 20×20, bg `--fab-badge-bg`, текст 12/16 500 `--fab-badge-fg`, «99+». Число = новые с момента, как ушли от низа.
- Hover: bg `--cell-hover`; pressed: scale .96; focus-visible: outline 2px `--accent` offset 2. `aria-label` «3 новых сообщения, прокрутить вниз» / «Прокрутить вниз».
- Появление/скрытие: fade + translateY 8→0, 150ms. Скрывается при нажатии (скролл `smooth` вниз) или когда пользователь сам доскроллил до низа (< 100px).
- Текста «Новые сообщения» на кнопке нет — число + стрелка достаточно и совпадает с MAX/Telegram. Если хочется подпись — tooltip через `title`.

## 6. Баннеры получения [DS:banner]
Компонент C6 (SPRINT-1 §6). Новое: **баннер с кнопками**. Раскладка: иконка 20 → текст `flex:1` → группа кнопок (gap 8) → `×` (если закрываемый). Кнопки внутри баннера: Ghost-текстовые h 32, radius 8, `--font-action-small` 14/20 500, padding 0 10, цвет `--text-link`; hover `--ghost-hover`. На mobile (<900) кнопки переносятся на вторую строку под текст (`flex-wrap`), выровнены влево с отступом иконки (padding-left 32).
«Проверить снова» в loading: Spinner 16 `--text-link` + текст «Проверяем…», остальные кнопки баннера disabled.

| Ситуация | Тип | Текст | Кнопки | Закрытие |
|---|---|---|---|---|
| 3+ ошибок сервера | error | Сервис GREEN-API недоступен. Повторим через **N с** (N — обратный отсчёт, `tabular-nums`, обновление 1/с; при 0 → «Повторяем…») | — | авто после успешного запроса |
| Webhook URL задан | error | Получение сообщений отключено: в настройках инстанса указан Webhook URL. Очистите его в личном кабинете и подождите около минуты | Открыть личный кабинет (external) · Проверить снова | по успеху «Проверить снова» |
| Инстанс отключён | error | Инстанс отключён от MAX. Отсканируйте QR-код в личном кабинете | Открыть личный кабинет · Проверить снова | по статусу `authorized`; composer disabled с плейсхолдером из SPRINT-2 §4 |
| suspended | warn | (из спринта 1) | — | × |
| Лимит тарифа | warn | Лимит бесплатного тарифа GREEN-API исчерпан. Часть функций недоступна до смены тарифа | — | × |
| (Could) входящие выключены | warn | В настройках инстанса выключено получение входящих сообщений — ответы не будут приходить | Открыть личный кабинет | × |
| офлайн | error | (из спринта 1) | — | авто |

Порядок в стеке: офлайн → сервис недоступен → инстанс отключён → Webhook → suspended → лимит → настройки. Одновременно показываем не больше 2 error + 1 warn; остальные ждут (следующий по приоритету появится, когда верхний закроется). `aria-live`: error assertive, warn polite; обратный отсчёт — `aria-live="off"` на числе, чтобы скринридер не читал каждую секунду.

Три строки текста на mobile 360 — норма; баннер растёт, min-h 40 не ограничивает.

- Лента: входящий одиночный · группа из 3 входящих · чередование in/out · плейсхолдер «не поддерживается» (in и out) · 4 статуса галочек + «не доставлено».

- Список: бейдж 1 / 12 / 99+ с strong-Title и синим временем; слот статуса `check-check` синий.
- FAB: без числа · с «3» · с «99+»; desktop и mobile.
- Баннеры: «недоступен, 16 с» · Webhook с 2 кнопками (desktop в строку, mobile в 2 строки) · «Проверить снова» loading · лимит warn с × · стек офлайн+Webhook.
- Вкладка: `(2) MAX-чат`.
