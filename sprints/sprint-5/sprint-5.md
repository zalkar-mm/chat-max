## Задача 1 — Live-демо в интернете
Связь: D-04, TZ §10.3, NFR-SEC-04, TC-03 · Приоритет: Must (задание: «желательно» — для впечатления обязательно)

### Описание и бизнес-логика
Ссылка на работающий сервис — первое, что откроет проверяющий: войдёт своим инстансом и попробует отправить сообщение. Демо должно открываться быстро, по HTTPS, из России и из других стран, и не требовать от проверяющего ничего, кроме его кредов.
В демо **не** зашиваются наши креды. Каждый входит своим инстансом.

### Как должно быть
- **Хостинг** статики на выбор разработчика; HTTPS обязателен.
- **Адрес** понятный (`max-chat-<ник>.<хостинг>` или свой домен), без случайных хешей.
- **Прямые ссылки и F5** на любом экране не дают 404.
- **Прокси** (только если спайк показал блокировку CORS): деплоится вместе с фронтом, пропускает **только** запросы к доменам GREEN-API, ничего не логирует (токен в URL!), описан в README.
- **Заголовки безопасности** из спринта 4 (задача 6) настроены на хостинге.
- **Деплой автоматический** из `main` (после зелёного CI). Каждый PR получает превью-ссылку — если хостинг позволяет.
- **Доступность из России:** проверить открытие без VPN — проверяющие из РФ и Казахстана. Если хостинг заблокирован или нестабилен в РФ — сменить хостинг.
- **Мета-данные:** `<title>`, описание, favicon, превью при отправке ссылки в мессенджер (обложка из DS).
- **Метрики трафика** не подключаем (лишнее + токен в URL запросов).

### Критерии приёмки
1. Демо открывается по HTTPS в режиме инкогнито на desktop и телефоне.
2. Демо открывается из РФ без VPN (проверка через знакомого / сервис проверки доступности из РФ).
3. F5 на главном экране не даёт 404.
4. Полный сценарий E-01…E-05 проходит на демо с живым инстансом.
5. Пуш в `main` → демо обновилось автоматически.
6. Ссылка, отправленная в Telegram, показывает превью с названием и обложкой.
7. В бандле демо нет кредов (поиск по токену в исходниках страницы).

## Задача 2 — README и инструкция локального запуска
Связь: D-03, KPI-5, TZ §10.2, TC-05, TC-06 · Приоритет: Must

### Описание и бизнес-логика
README — витрина работы. Проверяющий тратит на него 1–2 минуты: что сделано, как выглядит, как запустить, почему так. Инструкция запуска — отдельный обязательный пункт письма, поэтому у неё стабильная ссылка-якорь.
Язык — русский (задание на русском). Коротко, со скриншотами, без воды.

### Как должно быть
**Структура README:**
1. **Шапка:** название, одна строка о проекте, бейджи (CI, ссылка на демо), обложка или GIF главного сценария (≤ 5 МБ).
2. **Ссылки:** демо, видео, скриншоты.
3. **Что умеет** — 5–7 пунктов: вход по idInstance/apiTokenInstance, новый чат по номеру, отправка и получение текстовых сообщений, статусы, история после перезагрузки, адаптив, доступность.
4. **Что сознательно не делалось** и почему — одной строкой со ссылкой на «Максимально просто» из задания (медиа, группы и т.д.).
5. **Подготовка инстанса GREEN-API** со скриншотом настроек из ЛК:
   - создать инстанс MAX;
   - авторизовать по QR;
   - Webhook URL пустой;
   - включить получение входящих, исходящих и статусов;
   - где взять idInstance, apiTokenInstance (и apiUrl, если поле осталось).
6. **Быстрый старт (локальный запуск)** — якорь `#быстрый-старт`:
   - требования: версия Node, менеджер пакетов;
   - 2–3 команды: клонировать, установить, запустить;
   - какой адрес открыть;
   - если есть прокси — как он стартует локально (той же командой).
7. **Скрипты:** dev, build, preview, test, e2e, lint, typecheck — таблица «команда → что делает».
8. **Как устроено:** схема цикла получения (receive → обработать → delete), обработка ошибок и повторов, защита от дублей, хранение кредов — 5–10 строк + диаграмма.
9. **Почему так:** стек и ключевые решения разработчика — 5–10 строк (TC-06).
10. **Тестирование:** что покрыто, как запустить, как прогнать вручную на живом инстансе.
11. **Известные ограничения:**
    - получателя можно найти только по номеру +7/+375 (ограничение API GREEN-API);
    - квота бесплатного тарифа — 3 собеседника в месяц;
    - активна одна вкладка;
    - история хранится только в браузере.
12. **Структура проекта** — дерево верхнего уровня с пояснениями.
13. **Автор:** имя, Telegram, email, LinkedIn.

**Правила:**
- Все команды скопированы из README и реально выполнены на чистой машине (задача 4).
- Скриншоты — свежие, из финальной версии, светлые, без личных данных и кредов.
- Ссылки на файлы — относительные (работают в GitHub).

### Критерии приёмки
1. Человек, не видевший проект, по README запускает его локально за ≤ 5 минут (проверка на другом компьютере или в чистом контейнере / Codespaces).
2. Ссылка `…/README.md#быстрый-старт` (или эквивалент) открывает именно раздел запуска.
3. На скриншотах нет токенов, idInstance и чужих номеров телефонов (замазаны или тестовые).
4. Все ссылки в README рабочие.
5. Все команды из таблицы скриптов выполняются без ошибок.

## Задача 3 — Скриншоты и видео-презентация
Связь: D-05, TZ §10.3 · Приоритет: Should («при наличии» — делаем, это сильный плюс)

### Описание и бизнес-логика
Не каждый проверяющий заведёт инстанс и найдёт второй номер MAX. Видео доказывает, что главный сценарий работает по-настоящему: сообщение уходит в MAX и ответ с телефона появляется в чате. Скриншоты дают быстрый обзор без запуска.

### Как должно быть
**Скриншоты** (папка `docs/screenshots/` в репозитории, PNG, desktop 1440 и mobile 390):
1. Вход.
2. Блокирующий статус «Инстанс не подключён».
3. Главный экран пустой.
4. Новый чат с ошибкой номера.
5. Переписка с входящими и исходящими, статусами, разделителем дат (desktop).
6. Та же переписка на mobile.
7. Баннер «Нет соединения».

**GIF для README** (10–15 с): отправка → ответ появляется.

**Видео** (60–120 с, 1080p, без музыки или тихий фон, с субтитрами или голосом на русском):
1. 0–10 с: что это (титр: задание, стек, ссылка на демо).
2. Вход с инстансом (креды размыты).
3. Новый чат по номеру.
4. Отправка сообщения → телефон получателя рядом в кадре (запись экрана телефона или вставка) → сообщение пришло.
5. Ответ с телефона → появился в чате.
6. F5 → история на месте.
7. Офлайн → баннер → онлайн → догрузка.
8. Мобильная версия (5–10 с).
9. Финал: ссылки на демо и GitHub.

**Требования к видео:**
- Хостинг доступен без логина и из РФ: YouTube «по ссылке» + запасная копия (например, Google Drive или Яндекс Диск), ссылки в README.
- В кадре нет токена, idInstance, личных уведомлений на экране (режим «Не беспокоить»).
- Номера телефонов размыты или тестовые.

### Критерии приёмки
1. 7 скриншотов в репозитории, ссылки в README работают.
2. Видео 60–120 с, показан полный сценарий E-01…E-05 с реальным телефоном.
3. Видео открывается в инкогнито без логина; запасная ссылка работает.
4. Ни в одном кадре видео и скриншотов нет кредов.

## Задача 5 — Оформление репозитория GitHub
Связь: D-02, Q-08, NFR-SEC-01 · Приоритет: Must

### Описание и бизнес-логика
Проверяющий открывает репозиторий: смотрит описание, структуру, историю коммитов. Аккуратный репозиторий = аккуратный разработчик.

### Как должно быть
- **Публичный** репозиторий, понятное имя (`green-api-max-chat` или подобное).
- **About:** описание в одну строку, ссылка на демо в поле Website, темы (`react`, `typescript`, `green-api`, `max`, `messenger`).
- **Соцпревью:** обложка из DS.
- **Лицензия** MIT.
- **История коммитов:** осмысленные сообщения по Conventional Commits; без «fix», «wip», «asdf». Если история грязная — привести в порядок **до** отправки ссылки, после — не переписывать.
- **Ветки:** лишние удалены, `main` — основная.
- **Релиз** `v1.0.0` с коротким описанием (что сделано) — фиксирует сданную версию.

- **Папка `docs/`:** скриншоты, `copy.md`. Документы процесса (ТЗ, спринты) — включать или нет, решает автор (Q8).
- **Секреты:** проверка всей истории; если когда-либо коммитился реальный токен — **сменить токен в ЛК GREEN-API** и очистить историю.

### Критерии приёмки
1. Репозиторий открывается без логина, в About есть описание и ссылка на демо.
2. Есть релиз `v1.0.0`, совпадающий с задеплоенной версией.
3. `git log --oneline` читается как история разработки.
4. Сканер секретов по всей истории — чисто.
