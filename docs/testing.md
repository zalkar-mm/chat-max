# Тесты

Смежные темы: [data.md](data.md), [workflow.md](workflow.md).

Тестов ровно столько, чтобы доказать работу логики, а не «для галочки».

## 1. Что покрываем

| Что                                                                                             | Обязательно       | Инструмент                  |
| ----------------------------------------------------------------------------------------------- | ----------------- | --------------------------- |
| Чистые функции: номер → `chatId`, маппер уведомления → `Message`, форматтеры                    | да                | Vitest                      |
| Сторы: переходы (добавить сообщение, сменить статус, дедуп по `idMessage`)                      | да                | Vitest                      |
| Сервис опроса: `delete` после каждого уведомления, дедуп, `stop`/abort, backoff, один экземпляр | да                | Vitest + фейковые таймеры   |
| Фичи: вход, создание чата, отправка (валидация, пустое сообщение, Enter)                        | ключевые сценарии | Vitest + RTL + `user-event` |
| Вёрстка и стили                                                                                 | нет               | руками в браузере           |

Новая чистая функция или сервис — тест в том же коммите. Для логики опроса тест пишется раньше реализации.

## 2. Где лежат

- Рядом с кодом: `message-repository.ts` → `message-repository.test.ts`.
- Общая настройка — `src/test/setup.ts` (jest-dom, cleanup). Хелперы рендера — `src/test/`.
- Тестовые файлы не попадают в сборку (Vite тянет только достижимое из `main.tsx`).

## 3. Как пишем

- Имена — на русском, описывают поведение: `it('удаляет уведомление, даже если оно не текстовое')`.
- Сеть мокается на границе: repository подменяется через `vi.mock` / фейковый клиент. Реальных запросов в тестах нет.
- Асинхронные циклы — `vi.useFakeTimers()` и `await vi.advanceTimersByTimeAsync(ms)`.
- Состояние не течёт между тестами: сторы сбрасываются в `beforeEach`.
- Действия пользователя — `userEvent`. Исключение — фейковые таймеры, где `userEvent` зависает: там `fireEvent`.

## 4. Селекторы

1. `getByRole` с `name` — основной.
2. `getByLabelText`.
3. `getByText` — для статичного текста.
4. `data-testid` — только если у элемента нет роли.

Селекторы по классам и `container.querySelector` запрещены: Tailwind-классы — не контракт.

## 5. Ручная проверка перед сдачей

Сценарий ТЗ целиком на реальном инстансе: вход → новый чат по номеру → отправка → ответ из MAX
появился в чате. Плюс: неверные учётные данные, пропала сеть, мобильная ширина 360 px.

## Что запрещено

- ❌ Тест без `expect`, `it.only`/`test.only` — ESLint [инфра].
- ❌ Реальные сетевые запросы и реальные таймеры в тестах опроса — ревью.
- ❌ Селекторы по CSS-классам — ревью.
- ❌ «Проверено» без реального запуска `npm test` — [README §3](README.md#3-правила-для-ai-агента).
