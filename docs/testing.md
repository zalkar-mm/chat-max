# Тесты

Смежные темы: [data.md](data.md), [workflow.md](workflow.md).

Тестов ровно столько, чтобы доказать работу логики, а не «для галочки».

## 1. Пирамида

| Уровень      | Что                                                                                                               | Инструмент                        | Где                      |
| ------------ | ----------------------------------------------------------------------------------------------------------------- | --------------------------------- | ------------------------ |
| Unit         | Чистые функции и сторы — список ниже                                                                              | Vitest                            | `src/**/*.test.ts`       |
| Сервисы      | Опрос очереди: `delete` после каждого уведомления, дедуп, `stop`/abort, backoff, один экземпляр; автоперепроверка | Vitest + фейковые таймеры         | `src/**/model/*.test.ts` |
| Компонентные | Вход (все состояния), «Новый чат», поле ввода (Enter, Shift+Enter, лимит, IME), баннеры, лента                    | Vitest + RTL + `user-event` + MSW | `src/**/*.test.tsx`      |
| e2e          | 8 сценариев в браузере на моке API (§6)                                                                           | Playwright (Chromium)             | `e2e/*.spec.ts`          |
| Вёрстка      | Стили, мобильная ширина                                                                                           | руками в браузере (§5)            | —                        |

Unit-слой обязательно покрывает: нормализацию и проверку номера (все форматы), поля входа
(zod-схемы), перевод ответа API в ошибку и текст (все строки таблиц ошибок), разбор каждого
типа уведомления, дедуп (эхо, повтор, гонка), сортировку чатов, «статусы только вверх», хранение истории.

Новая чистая функция или сервис — тест в том же коммите. Для логики опроса тест пишется раньше реализации.

### Покрытие

`npm run test:coverage` (v8). Порог **80 %** по строкам, выражениям, функциям и веткам — на доменную логику
и слой API: `src/entities/**/{model,lib,api}/**`, `src/features/**/model/**`, `src/shared/api/**`,
`src/shared/lib/**` (без тестов, `*.types.ts`, `*-dto.ts`). Ниже порога — CI красный.
Настройка — `test.coverage` в `vite.config.ts`. UI в порог не входит: его страхуют компонентные тесты и e2e.

## 2. Где лежат

- Unit и компонентные — рядом с кодом: `message-repository.ts` → `message-repository.test.ts`.
- Общая настройка — `src/test/setup.ts` (jest-dom, cleanup, MSW). Хелперы рендера — `src/test/`.
- e2e — `e2e/` (хелперы — `e2e/helpers.ts`), конфиг — `playwright.config.ts`, типы — `tsconfig.e2e.json`.
  Vitest берёт только `src/**/*.test.{ts,tsx}`.
- Тестовые файлы не попадают в сборку (Vite тянет только достижимое из `main.tsx`).

## 3. Как пишем

- Имена — на русском, описывают поведение: `it('удаляет уведомление, даже если оно не текстовое')`.
- Сеть мокается на границе через MSW (`src/mocks/handlers.ts`, `setupServer` в `src/test/setup.ts`).
  Реальных запросов нет: `onUnhandledRequest: 'error'`. Сервисы с зависимостями — фейки через фабрику.
- Асинхронные циклы — `vi.useFakeTimers()` и `await vi.advanceTimersByTimeAsync(ms)`.
- Состояние не течёт между тестами: сторы сбрасываются в `beforeEach`.
- Действия пользователя — `userEvent`. Исключение — фейковые таймеры, где `userEvent` зависает: там `fireEvent`.

## 4. Селекторы

1. `getByRole` с `name` — основной.
2. `getByLabelText`.
3. `getByText` — для статичного текста.

## 5. Ручная проверка перед сдачей

Основной сценарий целиком на реальном инстансе: вход → новый чат по номеру → отправка → ответ из MAX
появился в чате. Плюс: неверные учётные данные, пропала сеть, мобильная ширина 360 px.

## 6. e2e

`npm run test:e2e`: Playwright сам поднимает `vite` с `VITE_API_MOCKS=true` на порту 5179, браузер — Chromium
(`npx playwright install chromium` один раз). Сценарии моков выбираются окончанием `idInstance` и метками
в тексте ([src/mocks/README.md](../src/mocks/README.md)); фиктивные креды — `token`, реального инстанса нет.

| Файл                    | Сценарий                                                                        |
| ----------------------- | ------------------------------------------------------------------------------- |
| `main-scenario.spec.ts` | E-01…E-05: вход → новый чат → отправка → ответ со статусами → смена чатов       |
| `sign-in.spec.ts`       | неверные креды (401); `notAuthorized` → «Проверить снова» → `authorized`        |
| `receiving.spec.ts`     | офлайн → онлайн с догрузкой (`context.setOffline`); повторная доставка (`#dup`) |
| `session.spec.ts`       | F5 сохраняет историю; выход очищает всё                                         |
| `tabs.spec.ts`          | две вкладки: активна последняя, «Использовать здесь» переключает обратно        |

Офлайн: Service Worker MSW отвечает и без сети, поэтому моки сами отвечают сетевой ошибкой,
пока `navigator.onLine === false`. Селекторы — те же, что в §4 (`getByRole`, `getByLabel`).

## 7. CI и pre-commit

- CI (`.github/workflows/ci.yml`) на каждый push и PR: `check:secrets` → lint → typecheck → format →
  `test:coverage` (сводка в summary job, отчёт — артефакт `coverage`) → build → e2e (отчёт — артефакт
  `playwright-report` при падении).
- `npm run check:secrets` (`scripts/check-secrets.mjs`) падает на hex-строке от 48 символов — так выглядит
  apiTokenInstance. Ложное срабатывание — пометка `check-secrets: allow` в строке.
- Pre-commit (`simple-git-hooks` + `lint-staged`, ставится скриптом `prepare`): ESLint `--fix`, Prettier и поиск
  секретов по застейдженным файлам.

## Что запрещено

- ❌ Тест без `expect`, `it.only`/`test.only` — ESLint (`@vitest/eslint-plugin`).
- ❌ Реальные сетевые запросы и реальные таймеры в тестах опроса — ревью.
- ❌ Селекторы по CSS-классам — ревью.
- ❌ «Проверено» без реального запуска `npm test` — [README §3](README.md#3-правила-для-ai-агента).
- ❌ Покрытие доменной логики и API ниже 80 % — порог в `vite.config.ts`, CI.
- ❌ Реальные креды в тестах и фикстурах — `check:secrets`, CI. Только заглушки вроде `token`.
- ❌ Тесты на живой инстанс в CI — ревью. Живой инстанс — только ручная проверка (§5).
