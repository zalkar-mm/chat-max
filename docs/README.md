# Правила проекта

Точка входа в `docs/`. Файлы читаются по требованию, целиком в контекст не грузятся.

Проект — тестовое задание: чат для отправки и получения текстовых сообщений в MAX через GREEN-API.
Главный критерий — **просто и чисто**: минимальный набор функций, без абстракций «на вырост».

## 1. Стек

| Что                  | Чем                                                                                |
| -------------------- | ---------------------------------------------------------------------------------- |
| Сборка               | Vite 8, React 19, TypeScript 6 (strict)                                            |
| Тесты                | Vitest (+ `@vitest/coverage-v8`), Testing Library, jsdom, MSW; e2e — Playwright    |
| Git-хуки             | `simple-git-hooks` + `lint-staged` (pre-commit: ESLint, Prettier, поиск секретов)  |
| Линтер / формат      | ESLint 9 flat config (`eslint.config.js`), Prettier                                |
| Стили                | Tailwind CSS v4 поверх токенов `src/styles/tokens.css`, `cn`, `cva`                |
| UI-примитивы         | свои в `shared/ui/` по дизайн-спеке, поведение — `radix-ui`, иконки `lucide-react` |
| Запросы              | axios (один инстанс) + TanStack Query (мутации)                                    |
| Клиентское состояние | Zustand (+ `persist` для кредов и темы)                                            |
| Роутинг              | React Router v7 (data router)                                                      |
| Формы                | react-hook-form + zod (`zod/mini` — вдвое меньше в бандле)                         |
| Сбой рендера         | `errorElement` корневого роута React Router                                        |
| Моки API             | MSW — тесты и dev-сценарии                                                         |

ESLint 10 не используем: плагины react и jsx-a11y его пока не поддерживают.
Требования: `design/` (спринт 1), `spints/` (спринт 2+). Новая библиотека — сначала строка в этой таблице.

## 2. Как устроены правила

- **У каждого факта одно место.** Остальные файлы ссылаются (`code-style §4`), а не копируют.
- **Документы описывают реальное состояние.** Чего нет в коде — помечено `[спринт N]`.
- **Блокер подкреплён проверкой** (ESLint, TypeScript, тест). Правило без проверки помечено «ревью».
- **Каждый файл заканчивается разделом «Что запрещено».**

## 3. Правила для AI-агента

1. **Не выдумывай в пробелах.** Решение техническое и обратимое — прими и запиши в теле коммита.
   Продуктовое или необратимое — остановись и спроси.
2. **Правило одного анализа.** Перед созданием файла проверь `shared/ui`, `shared/lib`, `entities/*`.
3. **Правило двух.** Логика появилась во втором месте — выносится в общее в том же коммите.
4. **Скопировать соседний файл и поправить пару строк — это долг, а не переиспользование.**
5. **Не следуй устаревшему коду молча.** Код расходится с правилом — правило важнее, сообщи.
6. **«Проверено» пишется, только если команда реально запускалась** (`npm run check`, `npm run build`).
7. **Изменил поведение или конфиг — обнови правило в том же коммите.**

## 4. Расхождения

| Конфликт                    | Что делать                                                          |
| --------------------------- | ------------------------------------------------------------------- |
| Код ↔ правило               | Правило важнее. Приводим код, если он в зоне задачи; иначе сообщаем |
| Правило ↔ правило           | Не решать самому. Спросить, ответ зафиксировать здесь               |
| Правило ↔ ТЗ / дизайн-спека | Спросить                                                            |
| Правило ↔ фактический стек  | Предложить правку правила первым коммитом `docs(rules): …`          |
