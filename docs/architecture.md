# Архитектура — FSD

Смежные темы: [imports.md](imports.md), [data.md](data.md).

## 1. Принцип

FSD — модель зависимостей, а не церемония. По пути файла понятно, что он делает и от чего зависит.

**Против оверинжиниринга:**

- Слайс, сегмент и папка появляются вместе с кодом. Пустых заготовок и `.gitkeep` «на будущее» нет.
- Обобщаем со второго использования ([README §3](README.md#3-правила-для-ai-агента), правило двух).
- Папка ради одного файла не заводится: `ui/message-bubble.tsx`, а не `ui/message-bubble/message-bubble.tsx`.
- Файл больше 200–300 строк — сигнал делить.

## 2. Слои

```
app       ← точка входа, роутер, провайдеры, глобальные стили
  ↓
pages     ← композиция страницы, без бизнес-логики
  ↓
widgets   ← крупные самостоятельные блоки (список чатов, окно переписки)
  ↓
features  ← действие пользователя (войти, создать чат, отправить сообщение)
  ↓
entities  ← бизнес-сущность (session, chat, message): модель, сервер, базовый UI
  ↓
shared    ← без предметной области: http-клиент, ui-примитивы, lib, config
```

- Слой импортирует **только слои ниже себя**.
- Импорт между слайсами **одного** слоя запрещён.
- Реакция одного слайса на другой (успешная отправка → сообщение в ленте) — связка уровнем выше
  (widget или page) либо общий стор сущности.

## 3. Что где живёт

### `app/`

`main.tsx`, `App.tsx`, `router.tsx`, `providers/` (QueryClient), `styles/index.css`
(вся конфигурация Tailwind). Запуск фоновых процессов (опрос уведомлений) — явный, здесь или
в хуке верхнего уровня, а не побочным эффектом импорта. Может импортировать всё.

Фоновые сервисы — модули с идемпотентными `start…()`/stop, их запускают эффекты `app/router/root-layout.tsx`.
Активна одна вкладка на сессию (`features/tab-leadership`, `BroadcastChannel`): получение, очередь отправки
и запись истории запускаются только в активной; неактивная показывает заглушку и не ходит в GREEN-API.
Вернувшись, вкладка сначала перечитывает историю из хранилища. Выход рассылается всем вкладкам.

### `pages/`

`pages/<name>/<name>.page.tsx`. Только композиция widgets/features и чтение URL-параметров.
Не вызывает repository и не читает сторы в обход хуков сущностей.

### `widgets/`

Крупный блок страницы, комбинирует features + entities: `chat-sidebar`, `chat-window`.

### `features/<slug>/`

```
features/<slug>/
  model/
    use-<slug>.ts          // вся логика: state, мутации, notify, navigate
    <slug>.schema.ts       // (форма) zod
  ui/
    <slug>.tsx             // чистый UI: только пропы (value + onX)
  lib/                     // (опц.) чистые хелперы фичи
```

Контейнер фичи (собирает хук `model/` и `ui/`) лежит **в корне слайса**: `features/sign-out/sign-out-button.tsx`.
Снаружи импортируют контейнер, а не хуки `model/`.

**`ui/` — только презентация.** Можно: `shared/ui`, `entities/*/ui`, `cn`, форматтеры.
Нельзя: `useMutation`/`useQuery`, сторы, `notify`, `useNavigate`, разбор ошибок API — это `model/`.
`useState` в `ui/` — только для чисто визуального состояния (открыт поповер). Состояние,
которое «знает про домен», — в `model/`.

### `entities/<entity>/`

| Сегмент  | Что внутри                                                                                     |
| -------- | ---------------------------------------------------------------------------------------------- |
| `api/`   | Всё про сервер: `<entity>-repository.ts`, `<entity>-dto.ts`, `<entity>-keys.ts`, хуки запросов |
| `model/` | Клиент: Zustand-стор, доменные типы, zod-схемы, чистые селекторы                               |
| `lib/`   | Чистые хелперы сущности (маппер DTO → модель, форматирование номера)                           |
| `ui/`    | Базовые презентационные компоненты, принимают готовую доменную модель                          |

Ключевое разделение: **`api/` про сервер, `model/` про клиент.**

### `shared/`

- `shared/api/` — http-клиент GREEN-API и типизированная ошибка. Без доменных репозиториев.
- `shared/ui/` — примитивы без домена по дизайн-спеке ([ui §3](ui.md#3-примитивы-sharedui)).
- `shared/lib/` — утилиты (`cn.ts`, `notify.ts`, `format-time.ts`).
- `shared/config/` — env и константы конфигурации.
- `shared/consts/` — `routes.ts` и прочие константы.

Сегменты — по назначению. ❌ `hooks/`, `types/`, `components/`, `utils/`, `helpers/`.

## 4. Предметная раскладка

| Слой / слайс                   | Что внутри                                                                            |
| ------------------------------ | ------------------------------------------------------------------------------------- |
| `entities/session`             | креды, «Запомнить меня», статус инстанса, `getStateInstance`, хранилище session/local |
| `entities/chat`                | чат, `checkAccount`, номер: нормализация / валидация / формат, аватар, элемент списка |
| `entities/message`             | сообщение, статусы, `sendMessage`, пузырь, разделитель дат                            |
| `features/sign-in`             | форма входа + проверка кредов                                                         |
| `features/instance-status`     | блокирующие экраны статусов, «Проверить снова», автоперепроверка `starting`           |
| `features/restore-session`     | сплэш, проверка сохранённых кредов при старте, «Нет соединения»                       |
| `features/sign-out`            | кнопка «Выйти» + полная очистка                                                       |
| `features/tab-leadership`      | одна активная вкладка на сессию, заглушка «Открыто в другой вкладке»                  |
| `features/toggle-theme`        | кнопка темы                                                                           |
| `features/create-chat`         | форма «Новый чат»                                                                     |
| `features/send-message`        | поле ввода, очередь отправки, «Повторить»                                             |
| `widgets/status-banners`       | баннеры сети и `suspended`                                                            |
| `widgets/chat-sidebar`         | шапка сайдбара + список чатов + пустое состояние                                      |
| `widgets/chat-window`          | шапка чата + лента + поле ввода                                                       |
| `pages/sign-in`, `pages/chats` | композиция экранов                                                                    |
| `app/`                         | провайдеры, роутер, гарды, ErrorBoundary, запуск/остановка сервисов                   |

Сброс всех доменных сторов при выходе — `features/sign-out/model`, он вправе вызвать очистку каждой сущности:
features импортируют entities.

## 5. Роутинг

- Все роуты — в `app/router.tsx`. Layout — через layout-route и `<Outlet />`.
- Пути — только константы из `shared/consts/routes.ts`:
  ```ts
  export const ROUTES = {
    SIGN_IN: '/sign-in',
    CHATS: '/',
    CHAT: (chatId: string) => `/chat/${encodeURIComponent(chatId)}`,
  } as const
  ```
- Открытый чат — в URL (`/chat/:chatId`), а не в сторе: на mobile URL решает, что показать — список или чат,
  «Назад» браузера работает сам.
- Гарды — `<RequireSession />` / `<RequireGuest />` layout-роутами в роутере, не HOC и не обёртка на странице.
- Статусы инстанса и сплэш — состояние, а не роуты: они живут внутри страницы входа / гарда.
- Экран сбоя — `errorElement` корневого роута (`app/crash/`): ловит ошибки рендера всех роутов и умеет выйти из сессии.

## Что запрещено

- ❌ Импорт вверх по слоям и между слайсами одного слоя — ESLint ([imports.md](imports.md)).
- ❌ Прямой вызов http-клиента из `features`/`widgets`/`pages` — ESLint (`no-restricted-imports`).
- ❌ Бизнес-логика в `*.page.tsx` и в `ui/` слайса — ревью.
- ❌ Пустые слайсы/сегменты, сегменты-по-типу (`hooks/`, `types/`) — ревью.
- ❌ Хардкод пути строкой, layout внутри страницы, HOC-гарды — ревью.
