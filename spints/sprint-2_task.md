# Спринт 2 — Новый чат, список чатов, отправка

**Цель:** пользователь создаёт чат по номеру телефона, видит его в списке, открывает и отправляет текстовое сообщение, которое приходит получателю в MAX. Интерфейс честно показывает статус каждого сообщения.

**В конце спринта показываем:** вход → «Новый чат» → номер +7/+375 → чат открыт → «Привет» → сообщение пришло на телефон получателя. Плюс ошибки: номер не в MAX, неверный формат, сбой отправки и повтор.

**Не входит (спринт 3):** получение ответов, счётчик непрочитанных, сохранение истории после F5. В этом спринте чаты живут до перезагрузки страницы — это ожидаемо.

**Экраны для дизайна:** S3 «Новый чат», элемент списка чатов, S4 «Чат» (шапка, лента, пузыри, поле ввода), статусы сообщений, mobile-версия чата.

**Зависит от:** спринт 1 (вход, каркас главного экрана, баннеры). Для живой проверки нужен получатель с MAX на номере +7 или +375.

Ссылки `FR-…`, `ST-…` — на `docs/TZ.md`, `[DS:…]` — на дизайн-спеку.

## Задача 1 — Форма «Новый чат»
Связь: E-02, FR-NEW-01…05, FR-NEW-09 · Приоритет: Must · [DS:S3]

### Описание и бизнес-логика
Чтобы написать человеку, пользователь вводит его номер телефона. Номер можно ввести как угодно — с «+», пробелами, скобками, через 8. Приложение само приводит его к виду, который понимает API.
Ограничение GREEN-API: найти человека по номеру можно **только** для России (+7) и Беларуси (+375). Мы говорим об этом заранее подсказкой, а не только ошибкой.

### Как должно быть
**Открытие:** кнопка «Новый чат» в шапке списка или «Начать новый чат» в пустом списке (заглушки из спринта 1 заменяются формой). Модалка или панель поверх списка — решает дизайн, по образцу web.max.ru.

**Состав:**
1. Заголовок «Новый чат», кнопка «Закрыть» (×).
2. Поле **«Номер телефона»**
   - Плейсхолдер `+7 999 123-45-67`.
   - Телефонная клавиатура на мобильном, автофокус при открытии.
   - Подсказка под полем: «Россия (+7) или Беларусь (+375)».
3. Кнопка **«Создать чат»**
   - Неактивна при пустом поле.
   - Во время проверки: спиннер, текст «Ищем в MAX…», поле неактивно.

**Приведение номера (при нажатии «Создать чат»):**
- Удаляются все символы, кроме цифр.
- 11 цифр, начинается с `8` → первая `8` заменяется на `7`.
- Примеры:
  - `+7 (999) 123-45-67` → `79991234567`;
  - `8 999 123 45 67` → `79991234567`;
  - `+375 29 123-45-67` → `375291234567`.

**Проверка формата** (при нажатии; при уходе из поля — только если поле непустое):
- Допустимо: 11 цифр, начинается с `7`, **или** 12 цифр, начинается с `375`.
- Ошибки:
  - пусто → «Введите номер телефона»;
  - иначе → «Номер должен быть российским (+7, 11 цифр) или белорусским (+375, 12 цифр)».

**Клавиатура:**
- Enter — «Создать чат».
- Esc — закрыть форму (не во время проверки).
- Фокус не уходит за пределы формы, пока она открыта; после закрытия возвращается на кнопку, которой её открыли.

**Ошибки** показываются под полем. Форма не закрывается, введённый номер остаётся.

**Состояния для дизайна:** default, фокус, ошибка формата, загрузка, ошибки от сервера (задача 2); desktop и mobile (на mobile — полноэкранно).

### Критерии приёмки
1. Пустое поле → «Создать чат» неактивна.
2. `8 999 123 45 67` → уходит запрос с номером `79991234567`.
3. `+375 29 123-45-67` → уходит запрос с номером `375291234567`.
4. `+996 555 123 456` → ошибка формата, запрос не отправляется.
5. `+7 999 123` → ошибка формата, запрос не отправляется.
6. Esc закрывает форму, фокус возвращается на «Новый чат».
7. Во время проверки Esc и повторный Enter ничего не делают.
8. Tab не выходит за пределы открытой формы.

## Задача 2 — Поиск номера в MAX и создание чата
Связь: E-02, FR-NEW-06…09, ST-15, ST-16, ST-18 · Приоритет: Must · [DS:S3-errors]

### Описание и бизнес-логика
MAX отправляет сообщения не по номеру, а по внутреннему идентификатору чата (`chatId`). Поэтому сначала спрашиваем у GREEN-API (`checkAccount`), есть ли у номера аккаунт MAX, и получаем `chatId`. Все дальнейшие отправки идут только по нему. Если отправлять «по номеру», ответ собеседника придёт с другим идентификатором и не попадёт в этот чат. Кроме того, на бесплатном тарифе это съест лишний слот квоты.
MAX следит за частыми проверками номеров и может ограничить аккаунт. Поэтому:
- если чат с этим номером уже есть — открываем его без запроса;
- проверяем только по нажатию кнопки, никогда «на лету» при вводе.

### Как должно быть
1. Номер уже есть в списке чатов → закрыть форму, открыть существующий чат, запрос **не** отправлять.
2. Иначе запрос `checkAccount` с номером.
3. Результат:

| Ответ | Что делаем | Текст пользователю |
|---|---|---|
| Аккаунт найден | Если чат с таким `chatId` уже есть — открыть его. Иначе создать: название — номер в формате `+7 999 123-45-67` / `+375 29 123-45-67`. Чат наверху списка, открыт справа (на mobile — сразу экран чата) | — |
| Аккаунта нет | Ошибка под полем | «Этот номер не зарегистрирован в MAX» |
| Инстанс не готов | Ошибка под полем + статус инстанса обновляется | «Инстанс не подключён к MAX. Проверьте его в личном кабинете» |
| Лимит проверок номеров (469) | Ошибка под полем | «Слишком много проверок номеров. Попробуйте через 2 часа» |
| Лимит тарифа (466) | Ошибка под полем | «Лимит бесплатного тарифа исчерпан. Смените тариф в личном кабинете GREEN-API» |
| Неверный формат (400) | Ошибка под полем | «Номер должен быть российским (+7, 11 цифр) или белорусским (+375, 12 цифр)» |
| Нет сети / сервер недоступен | Ошибка под полем | «Нет соединения с интернетом» / «Сервис GREEN-API недоступен. Попробуйте позже» |

- Приложение запоминает пару «номер → chatId» до конца сессии.

**Состояния для дизайна:** каждая ошибка из таблицы в форме; появление нового чата в списке.

### Критерии приёмки
1. Номер с MAX → чат появился первым в списке, открыт, в шапке номер в формате `+7 999 123-45-67`.
2. Тот же номер ещё раз (в любом написании) → открылся существующий чат, в сети нет нового `checkAccount`, дубля в списке нет.
3. Номер без MAX → «Этот номер не зарегистрирован в MAX», форма открыта, номер на месте.
4. Ответ 469 (мок) → текст про 2 часа.
5. Ответ 466 (мок) → текст про лимит тарифа.
6. Проверка номера не вызывается во время ввода — только по кнопке/Enter.

## Задача 3 — Список чатов
Связь: FR-LIST-01…03, FR-LIST-05 · Приоритет: Must · [DS:chat-list-item]

### Описание и бизнес-логика
Левая колонка — точка навигации: какие диалоги есть, в каком последнее сообщение, куда переключиться. Самые свежие — сверху, как в любом мессенджере. В этом спринте чаты появляются только через «Новый чат»; в спринте 3 — ещё и от входящих сообщений. Поэтому элемент списка сразу проектируем со счётчиком непрочитанных (показывать начнём в спринте 3).

### Как должно быть
**Элемент списка:**
- **Аватар-заглушка:** круг с цветом, вычисленным из `chatId` (у одного чата всегда один цвет), внутри иконка человека или первые цифры/буквы — по DS.
- **Название:** имя собеседника, если известно (со спринта 3), иначе номер в формате `+7 999 123-45-67`.
- **Превью последнего сообщения:** одна строка с обрезкой «…»; для своих сообщений префикс «Вы: ». Нет сообщений — «Нет сообщений».
- **Время последнего сообщения:**
  - сегодня → `14:05`;
  - вчера → «вчера»;
  - раньше → `28.09.26`.
- **Статус последнего своего сообщения** (иконка часов / галочка / ошибка) — по DS, по желанию.
- **Счётчик непрочитанных** — место заложено, логика в спринте 3.

**Поведение:**
- Сортировка по времени последнего сообщения, новые сверху. Новый чат без сообщений — наверх.
- После отправки сообщения чат поднимается наверх.
- Клик / Enter / Space — открыть чат. Активный чат подсвечен.
- Наведение и фокус видны.
- Список прокручивается независимо от шапки.

**Состояния для дизайна:** обычный, наведение, фокус, активный, длинное название (обрезка), длинное превью, своё сообщение («Вы: »), со счётчиком, статус «не отправлено».

### Критерии приёмки
1. Созданы 3 чата → в списке в порядке создания, последний сверху.
2. Отправка сообщения в нижний чат → он поднимается наверх, превью «Вы: <текст>», время `ЧЧ:ММ`.
3. Длинное превью обрезается в одну строку.
4. Активный чат подсвечен; при переключении подсветка переходит.
5. Список управляется с клавиатуры: Tab до элемента, Enter открывает.
6. Цвет аватара одного чата не меняется при повторном рендере.

## Задача 4 — Экран чата: шапка и лента сообщений
Связь: FR-VIEW-01…05, ST-03, NFR-SEC-03 · Приоритет: Must · [DS:S4], [DS:bubble]

### Описание и бизнес-логика
Правая панель (на mobile — отдельный экран) — сама переписка. Визуально — как web.max.ru: свои сообщения справа, собеседника слева, время внутри «пузыря», разделители дней.
Важно по безопасности: текст — только текст. Если собеседник пришлёт `<script>` или HTML, он должен отобразиться как буквы, а не выполниться.

### Как должно быть
**Шапка:**
- Аватар и название (как в списке), под названием — номер (если название — имя).
- На mobile слева кнопка «Назад» → к списку.

**Лента:**
- Свои сообщения справа, чужие слева; цвета — по DS.
- В пузыре: текст, время `ЧЧ:ММ`, у своих — статус (задача 6).
- Разделители дат: «Сегодня», «Вчера», `27 сентября` (для прошлого года — `27 сентября 2025`).
- Подряд идущие сообщения одного отправителя группируются (меньший отступ, «хвостик» только у последнего) — по DS.
- Переносы строк из текста сохраняются; длинные слова и ссылки переносятся, не растягивают пузырь.
- HTML в тексте отображается как обычный текст.
- Ссылки кликабельными не делаем (минимализм).
- Порядок — по времени сообщения.

**Прокрутка:**
- При открытии чата — сразу внизу, у последнего сообщения.
- После своей отправки — прокрутка вниз.
- (Поведение при входящих, когда пользователь прокрутил вверх, — спринт 3.)

**Пустой чат (ST-03):** по центру «Напишите первое сообщение».

**Состояния для дизайна:** пустой чат; короткое/длинное/многострочное сообщение; группа подряд идущих; разделитель дат; mobile с «Назад».

### Критерии приёмки
1. Новый чат → «Напишите первое сообщение».
2. Отправленное сообщение справа, время `ЧЧ:ММ`.
3. Текст `<b>привет</b>` отображается буквально, не жирным.
4. Текст с переносами строк отображается многострочно.
5. Строка из 200 символов без пробелов не выходит за пузырь, горизонтального скролла нет.
6. На 360 открытие чата показывает экран чата; «Назад» возвращает к списку, прокрутка списка сохранена.
7. После отправки лента прокручена к новому сообщению.

## Задача 5 — Поле ввода сообщения
Связь: E-03, FR-SEND-01…04, FR-SEND-10 · Приоритет: Must · [DS:composer]

### Описание и бизнес-логика
Поле ввода — самый используемый элемент. Поведение как в привычных мессенджерах: Enter отправляет, Shift+Enter — новая строка, поле растёт под текст.
Ограничение API: максимум 4000 символов в сообщении. Показываем счётчик заранее, чтобы пользователь не узнал о лимите по ошибке.

### Как должно быть
- Многострочное поле, плейсхолдер «Сообщение», растёт до 6 строк, дальше — прокрутка внутри.
- Автофокус при открытии чата (desktop; на mobile — нет, чтобы не выпрыгивала клавиатура).
- **Кнопка «Отправить»** (иконка, подпись для скринридера «Отправить»):
  - неактивна, если текст пустой или из одних пробелов/переносов.
- **Клавиатура:**
  - Enter — отправить;
  - Shift+Enter — новая строка;
  - при вводе через IME (набор иероглифов, автокоррекция с подтверждением) Enter не отправляет.
- **Лимит:**
  - счётчик `3850 / 4000` появляется с 3800 символов;
  - больше 4000 — счётчик красный, текст «Максимум 4000 символов», кнопка неактивна, Enter не отправляет.
- **Инстанс не готов** (статус сменился на не `authorized` / `suspended`): поле неактивно, плейсхолдер «Инстанс не подключён — отправка недоступна».
- **Черновик:** при переключении между чатами текст каждого чата сохраняется до конца сессии (по желанию; если не успеваем — поле очищается).

**Состояния для дизайна:** пустое, с текстом, многострочное (максимальная высота), счётчик, превышение лимита, неактивное (инстанс не готов).

### Критерии приёмки
1. Пустое поле или только пробелы → кнопка неактивна, Enter ничего не делает.
2. Shift+Enter добавляет перенос, не отправляет.
3. Поле растёт до 6 строк, затем появляется прокрутка внутри.
4. 3799 символов — счётчика нет; 3800 — есть.
5. 4001 символ → «Максимум 4000 символов», отправка невозможна.
6. Инстанс перешёл в `notAuthorized` → поле неактивно с поясняющим плейсхолдером.

## Задача 6 — Отправка сообщения и статусы
Связь: E-03, T-06, FR-SEND-05…09, ST-12, ST-13, ST-15 · Приоритет: Must · [DS:message-status]

### Описание и бизнес-логика
Отправка — через `sendMessage` по `chatId` (требование задания). Чтобы интерфейс ощущался быстрым, сообщение появляется в ленте **сразу** (статус «отправляется»), не дожидаясь сервера. Затем статус меняется на «отправлено» или «не отправлено».
При ошибке сообщение не пропадает: пользователь видит, что не ушло, и может повторить одним нажатием, не перепечатывая.
Если отправить три сообщения быстро подряд, получатель должен получить их в том же порядке. Поэтому сообщения уходят строго по одному.

### Как должно быть
**Процесс:**
1. Нажали «Отправить» / Enter → сообщение в ленте справа со статусом **«отправляется»** (иконка часов); поле очищено, фокус в поле; чат поднимается в списке.
2. Запрос `sendMessage`: `chatId` чата + текст (пробелы и переносы по краям обрезаны).
3. Успех → статус **«отправлено»** (одна галочка); запоминается идентификатор сообщения от API (нужен в спринте 3, чтобы не задублировать сообщение).
4. Ошибка → статус **«не отправлено»** (красная иконка) + под пузырём «Не отправлено. Повторить».
5. «Повторить» → то же сообщение снова «отправляется» (без дубля в ленте) → шаги 2–4.

**Очередь:** пока предыдущее сообщение «отправляется», следующие ждут своей очереди в статусе «отправляется» и уходят по одному в порядке ввода.

**Ошибки → текст под пузырём:**

| Ошибка | Текст | Дополнительно |
|---|---|---|
| Нет сети | «Нет соединения. Повторить» | Баннер «Нет соединения» (спринт 1) |
| Аккаунт ограничен (403 suspended) | «Не отправлено: аккаунт ограничен, можно писать только контактам. Повторить» | Жёлтый баннер (спринт 1) |
| Лимит тарифа (466) | «Не отправлено: исчерпан лимит бесплатного тарифа» (без «Повторить») | — |
| Ошибка проверки на сервере (400) | «Не отправлено: сервер отклонил сообщение. Повторить» | — |
| Сервер недоступен (5xx) / нет ответа 15 с | «Не отправлено. Повторить» | — |

**Состояния для дизайна:** «отправляется», «отправлено», «не отправлено» + «Повторить»; несколько сообщений в очереди; превью в списке со статусом ошибки.

### Критерии приёмки
1. Отправка «Привет» → в ленте сразу со статусом «отправляется», через ответ сервера — «отправлено»; сообщение пришло получателю в MAX.
2. В сети запрос `sendMessage` содержит `chatId` (не номер телефона) и текст без пробелов по краям.
3. Три сообщения подряд → получатель в MAX видит их в том же порядке; одновременно в полёте не больше одного запроса.
4. Отключили сеть → «Нет соединения. Повторить»; включили сеть, нажали «Повторить» → «отправлено», дубля в ленте нет.
5. Ответ 403 suspended (мок) → текст про ограничения + жёлтый баннер.
6. Ответ 466 (мок) → текст про лимит, кнопки «Повторить» нет.
7. Во время отправки можно продолжать печатать следующее сообщение.
