# Моки GREEN-API (MSW)

Dev-режим с моками: `VITE_API_MOCKS=true npm run dev`. Любой токен, кроме `wrong`, считается верным.
Сценарий выбирают **последние две цифры `idInstance`**:

| Окончание | `getStateInstance`                                                 |
| --------- | ------------------------------------------------------------------ |
| `01`      | `authorized` (и всё, что не в таблице)                             |
| `02`      | `suspended` — баннер «Аккаунт ограничен»                           |
| `03`      | `notAuthorized`                                                    |
| `04`      | `starting` → через 3 проверки `authorized`                         |
| `05`      | `blocked`                                                          |
| `06`      | `pendingPassword`                                                  |
| `07`      | `starting` навсегда — таймаут автопроверки                         |
| `08`      | `notAuthorized` → со 2-й проверки `authorized` («Проверить снова») |
| `29`      | HTTP 429                                                           |
| `50`      | HTTP 500                                                           |
| `99`      | ответ через 20 с — таймаут клиента (15 с)                          |

Токен `wrong` → HTTP 401 «Неверный idInstance или apiTokenInstance». Офлайн — вкладка Network в DevTools
(или `context.setOffline` в Playwright): пока `navigator.onLine === false`, моки отвечают сетевой
ошибкой, события копятся в очереди и приходят после переподключения.

## `checkAccount` — последние 4 цифры номера

| Окончание  | Ответ                                 |
| ---------- | ------------------------------------- |
| `0000`     | `exist: false` — «не зарегистрирован» |
| `4000`     | HTTP 400                              |
| `4030`     | HTTP 403 — инстанс не готов           |
| `4660`     | HTTP 466 — лимит тарифа               |
| `4690`     | HTTP 469 — лимит проверок номеров     |
| `5000`     | HTTP 500                              |
| любое иное | аккаунт найден, `chatId` из номера    |

## `sendMessage` — метка в тексте сообщения

`#400`, `#403` (аккаунт ограничен), `#466` (лимит тарифа), `#500` — соответствующий HTTP-ответ.
Без метки — успех через 0,6 с.

## Получение (спринт 3)

В dev после каждой отправки собеседник «отвечает»: эхо, «доставлено», ответ от «Анны», «прочитано».
Метка в тексте меняет сценарий:

| Метка          | Что приходит в очередь                              |
| -------------- | --------------------------------------------------- |
| `#photo`       | фото — плейсхолдер «не поддерживается»              |
| `#new`         | сообщение от нового собеседника «Борис» — новый чат |
| `#group`       | сообщение в группе — игнорируется                   |
| `#broken`      | битое событие — удаляется, цикл продолжает работу   |
| `#dup`         | один и тот же ответ дважды — в ленте одно сообщение |
| `#undelivered` | статус «не доставлено»                              |
| `#logout`      | инстанс разлогинился — баннер «Инстанс отключён»    |
| `#quota`       | событие лимита тарифа — жёлтый баннер               |

Окончание `idInstance`: `60` — задан Webhook URL, `61` — выключены входящие, `70` — очередь отвечает 500.
